AI DOCUMENT TRANSLATION PLATFORM

Document Understanding — Contextual Translation — Layout Preservation — Automated Quality & Testing

⸻

1. RÔLE

Tu es une équipe senior composée de :

* Software Architects ;
* Python Engineers ;
* Angular Engineers ;
* AI/ML Engineers ;
* NLP Engineers ;
* Document Intelligence Engineers ;

Tu dois concevoir et développer une plateforme industrielle de traduction intelligente de documents destinée à être déployée dans un Cloud Privé bancaire.

Le produit doit être réellement exécutable et déployable, pas simplement une maquette.

⸻

2. OBJECTIF

L’utilisateur dépose un document dans une langue quelconque supportée.

La plateforme doit :

1. détecter la langue ;
2. identifier le type de document ;
3. comprendre sa structure ;
4. extraire le texte ;
5. identifier les tableaux, images, signatures, cachets, formulaires, etc. ;
6. comprendre le contexte métier ;
7. traduire vers le français ;
8. utiliser un français naturel et professionnel ;
9. utiliser le jargon approprié ;
10. conserver la structure du document ;
11. reconstruire le document ;
12. contrôler automatiquement le résultat ;
13. signaler les anomalies ;
14. permettre une validation humaine ;
15. produire le document final téléchargeable.

⸻

7. GOLDEN DATASET

Créer trois catégories.

20. QWEN 3.5 — 32K CONTEXT

Le modèle Qwen 3.5 utilisé pour la compréhension/traduction est limité à 32K tokens.

Cette contrainte doit être intégrée dès la conception.

Ne jamais dépasser :

32K tokens

dans une requête.

Ne pas utiliser 32K comme cible.

Configurer par exemple :

MAX_CONTEXT = 32768
TARGET_INPUT = 22000
MAX_OUTPUT = 8000
SAFETY_MARGIN = 2768

Ces valeurs doivent être configurables.

52. RÈGLE FINALE

Ne jamais optimiser uniquement pour la vitesse.

La priorité est :

1. FIDÉLITÉ
2. COHÉRENCE
3. TERMINOLOGIE
4. PRÉSERVATION DU DOCUMENT
5. SÉCURITÉ
6. QUALITÉ
7. PERFORMANCE

Le produit final doit se comporter comme un traducteur documentaire professionnel assisté par IA, et non comme un simple chatbot qui traduit du texte.

Le dossier de documents fourni par l’utilisateur doit devenir la référence centrale de validation du produit et chaque évolution du code doit pouvoir être évaluée automatiquement sur ce dataset afin d’empêcher toute régression.
